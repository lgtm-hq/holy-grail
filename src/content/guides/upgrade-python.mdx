## What is a Python Version Upgrade?

When a new Python release is available, you may want to upgrade the Python version used
by your project's virtual environment. Unlike upgrading a standalone application, there
is no in-place upgrade path for virtual environments -- you need to create a new one
with the desired Python version.

This guide walks through the full process: installing the new Python version, removing
the old virtual environment, and recreating it with your existing dependencies.

## Install the New Python Version

First, install the desired Python version using pyenv:

```bash
# List available versions
pyenv install --list | grep -E " 3\.(1[0-9])"

# Install the new version
pyenv install <new-version>
```

Set it as the global version (or use `pyenv local` for per-project):

```bash
pyenv global <new-version>

# Verify
python -V
```

> uv can also install Python versions directly with `uv python install 3.12`. This does
> not require pyenv.

## Update Your Config File

Update the Python version constraint in your project's configuration file:

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

Update the `requires-python` field in your `pyproject.toml`:

```toml
[project]
requires-python = ">=3.12"
```

</Fragment>
<Fragment slot="pipenv">

Update the `[requires]` section in your `Pipfile`:

```toml
[requires]
python_version = "3.12"
```

</Fragment>
<Fragment slot="poetry">

Update the Python version constraint in your `pyproject.toml`:

```toml
[tool.poetry.dependencies]
python = "^3.12"
```

</Fragment>
</Tabs>

## Remove the Old Virtual Environment

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

Remove the `.venv` directory in your project:

```bash
rm -rf .venv
```

</Fragment>
<Fragment slot="pipenv">

From your project directory, run:

```bash
pipenv --rm
```

This removes the virtual environment associated with the current project.

If you need to remove it manually:

```bash
# Find the virtual environment location
pipenv --venv

# Remove it
rm -rf ~/.local/share/virtualenvs/<virtual-environment-name>
```

> Do **not** use `sudo` for this operation. These are user-owned directories.

</Fragment>
<Fragment slot="poetry">

Remove the environment associated with the old Python version:

```bash
# List environments
poetry env list

# Remove the old one
poetry env remove python3.11
```

Or remove all environments for the project:

```bash
poetry env remove --all
```

</Fragment>
</Tabs>

## Create a New Virtual Environment

With the old environment removed and the new Python version active, recreate the
virtual environment:

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

```bash
# Create a new environment with the desired version
uv venv --python 3.12

# Install dependencies
uv sync
```

**Verify the new environment:**

```bash
uv run python -V
```

</Fragment>
<Fragment slot="pipenv">

```bash
pipenv install
```

This will:

1. Detect the Python version from your updated `Pipfile` (or use the current global
   version)
2. Create a new virtual environment with that Python version
3. Install all dependencies from your `Pipfile`
4. Generate an updated `Pipfile.lock`

**Verify the new environment:**

```bash
pipenv shell
python -V
```

If you need to explicitly specify the Python version:

```bash
pipenv --python <new-version>
pipenv install
```

</Fragment>
<Fragment slot="poetry">

```bash
# Tell Poetry to use the new Python version
poetry env use python3.12

# Install dependencies
poetry install
```

**Verify the new environment:**

```bash
poetry run python -V
```

</Fragment>
</Tabs>

## Good to Know

### Check Python Release Schedule

Python releases follow a predictable annual cycle. Each version receives:

- **Full support** for 2 years after release
- **Security fixes** for an additional 3 years (5 years total)

Check the [Python Release Schedule](https://devguide.python.org/versions/) to see which
versions are currently supported.

### When to Upgrade

- **Security patches** (e.g., 3.11.8 to 3.11.9) -- Upgrade promptly; these are
  backwards compatible
- **Minor releases** (e.g., 3.11 to 3.12) -- Test your project first; some
  deprecations may affect your code
- **End-of-life versions** -- Upgrade as soon as practical to maintain security

### Keep the Old Version Available

You do not need to uninstall the old Python version from pyenv. Having multiple versions
installed lets you switch back if needed:

```bash
# List all installed versions
pyenv versions

# Switch back if needed
pyenv global <old-version>
```

## Troubleshooting

### Tool Uses the Wrong Python Version

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

If uv creates the environment with an unexpected Python version:

```bash
rm -rf .venv
uv venv --python 3.12
uv sync
```

You can also pin the version in `pyproject.toml`:

```toml
[project]
requires-python = ">=3.12"
```

</Fragment>
<Fragment slot="pipenv">

If Pipenv creates the environment with an unexpected Python version:

```bash
# Explicitly specify the version
pipenv --rm
pipenv --python <new-version>
pipenv install
```

</Fragment>
<Fragment slot="poetry">

If Poetry uses the wrong Python version:

```bash
# Remove and recreate with the correct version
poetry env remove --all
poetry env use python3.12
poetry install
```

</Fragment>
</Tabs>

### Dependencies Fail to Install on New Python Version

Some packages may not yet support the newest Python version:

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

```bash
# Check which packages fail
uv sync 2>&1 | grep -i error

# Check package compatibility on PyPI
uv pip index versions <package_name>
```

</Fragment>
<Fragment slot="pipenv">

```bash
# Check which packages fail
pipenv install 2>&1 | grep -i error

# Check package compatibility on PyPI
pip index versions <package_name>
```

</Fragment>
<Fragment slot="poetry">

```bash
# Check which packages fail
poetry install 2>&1 | grep -i error

# Check package compatibility on PyPI
pip index versions <package_name>
```

</Fragment>
</Tabs>

Consider temporarily pinning to the previous Python version until all your dependencies
support the new one.

### "Python version not found"

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

```bash
# Install directly with uv
uv python install <version>

# Or install via pyenv
pyenv install <version>
```

</Fragment>
<Fragment slot="pipenv">

```bash
# Verify it is installed
pyenv versions

# If not installed, install it
pyenv install <version>

# Ensure pyenv shims are up to date
pyenv rehash
```

</Fragment>
<Fragment slot="poetry">

```bash
# Install the version
pyenv install <version>

# Ensure pyenv shims are up to date
pyenv rehash

# Tell Poetry to use it
poetry env use python<version>
```

</Fragment>
</Tabs>

### Virtual Environment Still References Old Python

After upgrading, verify the environment uses the correct Python:

<Tabs tabs={["uv", "pipenv", "poetry"]}>
<Fragment slot="uv">

```bash
uv run python -V
uv run which python
```

If it still shows the old version, remove and recreate:

```bash
rm -rf .venv
uv venv --python 3.12
uv sync
```

</Fragment>
<Fragment slot="pipenv">

```bash
pipenv shell
which python
python -V
```

If it still shows the old version, remove and recreate:

```bash
exit
pipenv --rm
pipenv install
```

</Fragment>
<Fragment slot="poetry">

```bash
poetry run python -V
poetry run which python
```

If it still shows the old version, remove and recreate:

```bash
poetry env remove --all
poetry env use python3.12
poetry install
```

</Fragment>
</Tabs>

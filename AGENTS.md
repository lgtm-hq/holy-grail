# AGENTS.md

## Cursor Cloud specific instructions

Holy Grail is a single **static Astro documentation site** (no backend, database, or containers). Standard commands live in `README.md` and `package.json` scripts; below are only the non-obvious caveats for this environment.

### Toolchain
- Package manager is **Bun** (`bun.lock`); Python tooling uses **uv** (`pyproject.toml`, `uv.lock`) and is only needed for linting. Both `bun` (`~/.bun/bin`) and `uv` (`~/.local/bin`) are installed in the VM snapshot and are on `PATH` in login shells via `~/.bashrc`.
- Dependencies are refreshed automatically on startup by the update script (`bun install`, which also runs the `postinstall` theme sync, plus `uv sync`).

### Running the dev server
- Start with `bun run dev` (Astro dev server, port **4321**).
- The site's `base` defaults to `/holy-grail` (for GitHub Pages). For local development at the root path, run `ASTRO_BASE=/ bun run dev` so routes are served from `/` instead of `/holy-grail/`.

### Build and search
- `bun run build` runs `astro check` → `astro build` → `pagefind` indexing → `./scripts/sync-assets.sh pagefind`.
- Full-text **search (Pagefind)** requires a build first: the search index is generated by `bun run build` and copied into `public/pagefind`. Without a prior build the search page has no index.

### Lint / test
- Lint: `uv run lintro chk` (auto-fix with `uv run lintro fmt`).
- There are currently **no automated unit/E2E tests** in the repo (`bun test` reports "No tests found"; `.github/workflows/quality-e2e.yml` skips because there is no `playwright.config.ts`).
